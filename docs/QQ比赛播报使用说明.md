# BingoTools v17.2.0：联机房间与 QQ 比赛播报

## 第一次使用

下载 Windows 64 位 exe 后双击打开，无需安装 Go、Node.js、Python，也不需要运行 roomserver.exe。
程序默认连接 `https://bingotools-qqbot-api.onrender.com`，普通用户无需输入使用密钥。
Windows 10/11 需要 WebView2，未安装时按程序提示联网安装。程序尚未代码签名。
独立 HTML 可直接用 Chrome/Edge 打开；抖音原生取流和窗口置顶需要桌面版。

首次显示“正在连接 / 唤醒服务器”时请稍候，最多等待 90 秒。
更换服务器仅需进入 **全局设置 → 服务器连接（高级设置）**。
网页和 exe 分别保存会话与裁判信息；不要复制或分享应用存储中的会话凭据。

**房间、挂载、历史及定时播报设置仅存在服务器内存。休眠、重启或重新部署后可能全部清空。**
UptimeRobot 可以帮助保持在线，但不是数据库，不能恢复丢失的数据。

## 开始比赛

1. 设置左右选手名字、直播间和计分规则。
2. 在比赛计时区点击 **开始比赛**，填写裁判名字、平台和直播间。
3. 点击 **保存并开始**，自动创建房间。默认准备倒计时为 5 秒。
4. 倒计时结束后正式计时，并排队发送 QQ 开始通知。

也可进入 **比赛列表 → 创建等待房间**，先让其他人加入，再用计时区按钮开始。
在比赛列表中可设置 0–60 秒准备倒计时。
裁判信息保存在当前设备；这里的“裁判”始终是名字，不是直播标题。
红蓝方不需填写直播标题，群消息不显示房间识别码。

## 加入与同步

在比赛列表点击“加入”，或输入裁判提供的识别码，然后填写自己的显示名字。
每个房间最多 10 人，包含裁判。普通加入者只读查看；识别码不会授予裁判权限。

裁判的棋盘、计分设置与比分会同步，变更约 1 秒合并上传；加入者每 3 秒读取。
在线状态约 10 秒更新，30 秒无心跳显示离线。断线时保留上次画面，提示数据可能过期。
版本冲突时读取服务器最新状态并提示重新操作，不强行覆盖别人的更新。
同一设备同一会话不要同时用多个窗口主持同一个房间。

比赛列表可查看成员并由裁判移出成员。裁判离线不会自动把权限交给别人。
清除浏览器数据或丢失会话后无法凭房间码恢复裁判权限，请联系开发者处理。

## 挂载、接管与历史

- **挂载并暂停**：保存当前棋盘、比分及累计用时，暂停计时，放入挂载列表。
- **接管**：输入新裁判及其直播间完整地址；服务器只允许一人成功接管。
  沿用同一场比赛的比分和用时，开始通知不会再发一次。等待中的比赛接管后仍需点击开始。
- **比赛结束**：确认当前最终比分，停止计时，加入历史并排队发送结束通知。
- **历史重新挂载**：由原裁判或开发者发起，保留棋盘与比分，作为新比赛，用时归零。

比赛列表支持识别码复制、记录详情和历史查看。开发者可删除挂载记录。
小窗支持拖动、调整大小及字体，展示同步棋盘和比分；桌面“置顶”作用于应用窗口。

## QQ 播报

开始、结束消息发送到管理员配置的固定 QQ 群。群里 @机器人可查询进行中的比赛：
裁判及直播间、红蓝方名字与比分、比赛用时和最后同步时间。
比分同步本身不刷群；离线时比分可能停留在上次同步值，请关注同步时间。
挂载比赛不出现在进行中查询里。

比赛状态与播报状态分开显示：即使 QQ 发送失败，计分与比赛仍可继续。
“排队发送中”需要等待；明确失败可在比赛列表重试；“结果未确认”须先核对群消息，程序不自动重发。
所有群消息共用有界队列，并受 QQ 平台限制；排队满或频率过高会明确显示错误。

普通用户无需邀请码，任何取得服务地址的人都能创建比赛并触发规定格式的群消息。
当前有频率限制，但不能保证阻止恶意刷群。只有固定群，不允许用户指定消息目标或任意消息内容。

## 开发者与定时汇总

管理员在 Render 环境变量设置独立的 `BINGOTOOLS_DEV_CODE`，不要使用 QQ AppSecret 代替。
不配置时开发者管理关闭，普通房间功能仍可使用。

在 **全局设置 → 开发者模式** 输入识别码。服务器验证后授权 8 小时；关闭后立即撤销本会话管理权限。
仅开发者可以开启或修改全局定时群汇总：默认关闭，默认间隔 5 分钟，最小 5 分钟。
由服务器统一发送，不会因为多开客户端重复发送；没有比赛时不发。
服务器重启后设置回到默认关闭，需重新开启。

## UptimeRobot 保活

在自己的 UptimeRobot 账号建立 HTTP(s) 监测：

- 名称：BingoTools QQ Bot
- URL：`https://bingotools-qqbot-api.onrender.com/health`
- 间隔：5 分钟
- 不需要 Authorization、使用密钥或 QQ AppSecret。

保存后检查监测状态为 Up，并核对 Render 收到健康检查请求。
该请求不发送 QQ 群消息。免费额度与服务条款以平台当前显示为准。
当前 QQ 使用长连接；服务休眠后，单靠群里 @机器人不能可靠唤醒，已错过的消息也不保证补收。

## 旧版兼容

v17.1.0 的 v1 比赛接口继续使用原 BOT_CLIENT_KEY；v17.2.0 不要求普通用户填写它。
旧版和新版的比赛都可由群查询显示，但旧比赛不会自动迁入联机房间。
新版本不会恢复旧网页缓存为新房间；首次升级前请先结束旧版比赛。

## 发布与验收

发布包含 Windows exe、exe + 本说明的 zip、SHA256 校验文件，以及独立 HTML。
自动测试覆盖服务权限、双客户端同步、通知去重、挂载接管和失败处理。
真实 QQ 群联调及 Windows 桌面实机点击测试需单独验收，不能以构建成功代替。
