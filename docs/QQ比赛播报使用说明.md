# BingoTools 比赛播报使用说明

适用版本：Windows v17.1.0，以及同版本独立 HTML。

## 第一次使用

1. 从本仓库 Releases 下载 `BingoTools-v17.1.0-windows-amd64.exe`，双击运行。
   不需要安装 Go、Node.js 或 Python，也不需要在本机启动机器人服务器。
2. 打开 **全局设置 → QQ Bot 连接**。
3. 服务地址填写 `https://bingotools-qqbot-api.onrender.com`。
4. 使用密钥填写管理员提供的 `BOT_CLIENT_KEY`，点击 **保存 QQ Bot 配置**。
   不要填写 QQ AppSecret。发布的 exe 不包含任何人的使用密钥。

Windows 10/11 64 位需要 Microsoft WebView2 Runtime。程序内嵌了官方安装引导：
未安装时按提示联网安装，再启动程序。程序目前未进行代码签名。

网页和 exe 各自保存配置，从网页切换到 exe 时需要首次重新填写。
独立 HTML 可直接用 Chrome/Edge 打开，设置同一个服务地址和使用密钥。
桌面版保留 B站/抖音原生取流、Bingo Maker 和离线播放库。

## 开始比赛

1. 在左右直播设置中设置红蓝方选手名字和直播间，检查计分区名字。
2. 在 **比赛计时** 区点击 **开始比赛**。
3. 填写 **裁判直播平台**、**裁判直播间地址或房间号**、**裁判**（昵称/名字）。
   这里的“裁判”就是 QQ 开始、结束和查询消息里的“裁判”，不再指直播标题。
4. 点击 **保存并开始**：计时器启动，程序向固定 QQ 群发送比赛开始通知。

裁判信息自动保存在当前设备，下次自动填充，仍可修改。
旧版本保存的“裁判直播间标题”内容会保留在“裁判”里，请首次检查并改成裁判名字。
红蓝方不需要填写直播间标题，通知仅展示选手名字和直播间地址。

地址可以填写完整链接，例如 `https://live.bilibili.com/123456`；
填写房间号时，请选择对应平台。不要把整段分享文案、昵称填进地址栏。

## 比分同步与群查询

比赛开始后，程序读取红蓝方选手下方的总分，与已进行时间一起同步到 Render。
分数变动后约 1 秒同步，比赛进行中每 15 秒同步一次；同步本身不向群刷消息。

在固定群里 **@机器人**，机器人显示正在进行的比赛：

- 裁判与裁判直播间；
- 红蓝方选手名字及最新同步的比分；
- 比赛已进行的时间与最后同步时间。

已进行时间标明“截至同步”，关闭软件、断网或电脑休眠后不再代表实时状态。
多个使用者可以同时开始各自的比赛。

## 结束比赛

点击 **比赛结束**，检查并确认最终得分。计时暂停，程序发送裁判、红蓝方名字、
最终得分和比赛用时。结束后该比赛不再出现在群查询中。

结束失败时，程序保留这次最终比分和用时，再次点击结束会重试同一次请求。
若发送结果未知，请先检查 QQ 群，程序不会自动重复发送。必要时可选择 **仅本地结束**，
但该选项不补发通知，也不能保证云端记录已经结束。

## 失败处理与使用限制

- 使用密钥错误：在全局设置重新填写管理员提供的使用密钥。
- 首次请求较慢：Render 免费服务可能正在唤醒，页面最多等待约 90 秒。
- 地址校验失败：检查裁判和左右选手的地址、平台选择。
- QQ 平台拒绝发送：页面会显示错误，失败不会清空 Bingo 计分。
- 开始播报失败：可选择 **仅本地开始**；该场比赛不会出现在群查询中。
- 当前使用内存保存比赛，不需要数据库；Render 重启/重新部署会清空比赛记录。
  旧比赛无法继续同步时，先核对群消息，再仅本地结束并开始新比赛。
- 免费服务不保证全天在线；服务休眠期间 @机器人可能暂时没有回复。
- 同一个比赛页面不要同时在多个窗口操作，以免不同窗口的比分互相覆盖。

## 发布内容

- `.exe`：Windows 64 位可执行文件，前端与播放库已内嵌；
- `.zip`：同一个 exe 加本使用说明；
- `SHA256SUMS.txt`：下载文件校验值。

exe 与网页调用相同 Render 服务。QQ AppSecret 和目标群配置只保留在服务端，
客户端只保存使用密钥。发给其他使用者时，请由管理员单独提供使用密钥。
