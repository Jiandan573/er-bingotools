# 房间服务 v2 接口

所有 v2 路由为 POST JSON，前缀 `/api/v2`。响应为 `{ok, instance, serverTime, ...}`。
`/health` 使用 GET，免鉴权。`/session` 公开创建自动会话，返回 token；后续请求使用 `Authorization: Bearer <token>`。
会话最长闲置 30 天，服务器重启立即失效。普通用户不需要手填 token。

| 路由 | 请求要点 | 行为 |
| --- | --- | --- |
| /session | 空对象 | 生成随机会话 |
| /list | 空对象 | 房间、挂载、历史摘要及当前开发者状态 |
| /create | request_id, match, board, scores | 创建等待房间；同 request_id 重试不重复创建；开发者可同时持有多个未结束房间 |
| /get | id | 读取完整房间和调用者权限 |
| /join | id, name | 加入只读成员 |
| /heartbeat | id | 更新成员在线状态 |
| /leave | id | 离开；裁判须先结束或挂载 |
| /update | id, revision, board, scores | 仅裁判／开发者，按版本更新 |
| /kick | id, revision, member | 裁判移出成员 |
| /start | id, revision | 立即开始比赛并播报；重复请求不重置 |
| /end | id, revision, board, scores | 锁定终局，通知结果与房间状态分离 |
| /mount | id, revision | 暂停挂载 |
| /takeover | id, revision, referee | 原子接管；冻结期间不累计用时 |
| /remount | id, request_id | 原裁判／开发者将已结束比赛转为新挂载；成功后原已结束记录删除；同 request_id 重试幂等 |
| /retry | id, kind=start或end | 仅重试明确失败通知 |
| /delete | id（不校验 revision） | 房主可删自己任意状态房间；管理员可删他人挂载/已结束 |
| /dev-auth | code | 验证 BINGOTOOLS_DEV_CODE，8 小时授权 |
| /dev/logout | 空对象 | 撤销本会话开发者授权 |
| /dev/settings | 空对象，或 enabled + interval | 仅开发者读取／更新定时汇总 |
| /roster | 空对象 | 已连接用户读取服务端共享选手名册；不含棋盘和房间识别码 |
| /roster/push | entries | 仅开发者将本地选手名册合并到服务端；同来源去重 |

match 沿用 v1 的 referee / left / right 结构；referee.title 对应“裁判名字”。
board 包含 25 格 red/blue/first/marks/redTime/blueTime，结算与加分、格子文字及白名单计分设置 scoring。
scores 为 `{red, blue}`。客户端提交总分，服务端校验范围；此工具不防范裁判本人故意填写错误比分。

room 的状态为 waiting / playing / mounted / ended（兼容保留 countdown）。房间摘要不含棋盘。
详细响应包括 canControl、isHost、成员在线状态、elapsed_seconds 和 delivery.start/end。
通知状态为 pending / sent / failed / unknown。未知结果不自动重发。
409 表示版本或状态冲突；401 表示会话失效；403 表示权限不足；429 表示限流。
成员加入、在线心跳和通知结果不争用棋盘版本，防止无关变动回滚计分。
客户端无推送通道：观众约 0.8s 轮询 `/get`（兼心跳），裁判约 2.5s；裁判本地改分约 0.4s 防抖后 `/update`。普通观众 `canControl=false`，`/update` 等写接口由服务端 `host()` 拒绝。
加入房间仅通过比赛列表「加入」；**不再**展示或使用房间识别码（QQ 播报亦不附带）。开发者识别码仅用于管理员解锁。

限制：每 IP 每分钟 5 场创建；普通会话最多 1 场非挂载未结束比赛（开发者／管理员可同时创建多个）；10 人/房间；
2,000 条比赛记录（优先清理最旧结束记录）；群通知队列 100 条；请求体上限 128 KiB。
Render 下使用代理追加的最右侧 X-Forwarded-For 地址；本地使用 socket 地址。
没有公开任意 URL 转发、整库覆盖或任意群消息接口。

选手名册通过 `/roster` 读取、`/roster/push` 写入；普通用户可读取，上传需要开发者权限。

选手列表 / 挂载列表 / 历史赛程的同步范围见 `docs/服务端同步清单.md`。完整服务端需求见 `docs/服务端需求说明.md`。

## 维护

修改主页面后运行 `node scripts/embed-rooms.mjs`，再运行 `node scripts/make-standalone.mjs` 与 `node scripts/sync-v18-layout.mjs`。
房间客户端源码在 frontend/room 中，构建后内嵌到 HTML，无新增客户端 npm 构建依赖。
Go 的 CallRoomService 仅转发固定路径，拒绝重定向，保留 HTTP 错误码。
部署维持 Render 单实例免费 Node Web Service；v2 不使用数据库，且不要复制本地密钥文件到仓库。
`/remount` 会删除原已结束房间：须重新部署 `qqbot-service` 后云端才生效；仅刷新前端不够。
